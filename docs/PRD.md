# kosdap — 삼성전자/SK하이닉스 추정가 서비스 PRD

## 1. 목표
삼성전자(005930)와 SK하이닉스(000660)의 **국내 장(KRX) 마감 이후 ~ 다음 거래일** 추정가격을 계산해서 보여주는 웹사이트.

추정가격은 LLM이 임의로 생성하는 것이 아니라, **실시간 시장 데이터를 수집해 정량적으로 계산**한다. 계산 로직은 초기엔 사람이 정한 가중합(weighted score)으로 시작하고, 예측 이력이 쌓이면 LightGBM/XGBoost로 가중치를 자동 학습하는 방향으로 고도화한다.

## 2. 핵심 차별점
1. **예측 근거를 투명하게 공개** — 상승요인/하락요인을 항목별로 나열
2. **예측 정확도를 스스로 기록·공개** — 예측 vs 실제, MAPE/RMSE를 매일 자동 계산해서 숨기지 않음
3. **주말/장마감 구간도 실데이터 기반으로 추정** — 아래 "3. 핵심 데이터 소스" 참고

## 3. 핵심 데이터 소스

### 3.1 1차 신호 — 토큰화 주식 / 무기한선물 (24/7 실거래)
과거엔 "국내 장이 닫히면 추정할 방법이 없다"는 게 문제였으나, 2026년 SK하이닉스 나스닥 ADR 상장 이후 크립토 거래소에 아래 상품이 상장되어 **주말을 포함한 24/7 실시간 가격 신호**로 사용 가능. (2026-08-06 실측 검증 완료 — `services/predictor/collectors/tokenized.py`)

| 종목 | 상품 | 티커 | 특징 |
|---|---|---|---|
| 삼성전자 | Bybit 무기한선물(linear perp) | **SAMSUNGUSDT** | 실측 lastPrice ~175 USDT, 24h volume ~40k. **1순위 신호** |
| SK하이닉스 | Bybit 무기한선물(linear perp) | **SKHYNIXUSDT** | 실측 lastPrice ~1176 USDT, 24h volume ~80k. **1순위 신호** |
| SK하이닉스 | Binance bStocks (1:1 담보 토큰) | SKHYB/USDT | 실측 확인됨(가격 정상 수신). 삼성전자는 Binance에 상장 안 됨 — 교차검증용 보조 소스 |

> 초안에서는 SMSN(Hyperliquid)을 삼성전자 신호로 가정했으나 실측 결과 Hyperliquid 기본 perp universe(232종)에 SMSN이 없어 폐기. Bybit이 두 종목 모두 하나의 API로 커버해서 최종적으로 Bybit을 1순위로 채택.

**베이시스 보정 (중요 — 실측 중 발견된 버그)**: 토큰가는 **USDT**, KRX 종가는 **KRW**로 통화 단위가 다르기 때문에 `(토큰가 − KRX 종가)`처럼 직접 뺄셈하면 안 된다 (실제로 이렇게 짰다가 -99% 같은 값이 나오는 걸 확인하고 수정함). 대신 **"KRX 마감일의 토큰 종가" 대비 "현재 토큰가"의 변동률**(USDT/USDT, 동일 통화)을 구해서, 그 비율만 KRW 종가에 곱해 추정가를 계산한다. Bybit 일봉(kline) API로 마감일 기준가를 조회한다.

### 3.2 2차 신호 — 해외 상관 종목 (보조 설명 요인)
- Micron (MU) — 메모리 동종업계 최근접 지표
- Nvidia (NVDA) — HBM 수요 (SK하이닉스 상관도 특히 높음)
- SOXX / SMH — 반도체 업종 지수
- TSMC (TSM) — 글로벌 파운드리 사이클
- 나스닥/S&P 선물 — 전체 위험자산 심리
- KOSPI200 야간선물(Eurex) — 한국 지수 자체의 해외 시간대 신호
- USD/KRW, DXY, 미국 10년 국채금리, VIX — 매크로 팩터
- BTC/ETH — 보조 리스크 센티먼트 (가중치 낮게)

### 3.3 3차 신호 — 국내 수급 (일 단위 지연 데이터, 실시간 아님)
- 공매도비율, 외국인/기관 순매수 — **하루 1회 장마감 후 갱신**되므로 다음날까지는 고정값으로 취급 (10분마다 조회해도 값이 안 바뀜에 유의)

### 3.4 KRX 자체 시간외 데이터 (추정이 필요 없는 구간)
- 장후 시간외 단일가 (16:00~18:00): 실제 체결가이므로 "추정"보다 우선
- 장전 시간외 (07:30~08:30): 동일

## 4. 계산 로직

### 4.1 현재 구현: 종목별 Ridge 회귀 계수 (수동 가중치에서 교체됨)
처음엔 PRD 초안대로 손으로 찍은 가중치(token 35~45%, Nvidia 10~15% 등)를 썼으나, 과거 데이터로 백테스트한 결과와 나란히 비교해보니 "손으로 찍은 가중치가 데이터로 적합한 것보다 확실히 나쁘다"고 말할 근거가 없었다 (아래 4.3 참고). 그래서 재현 가능하고 데이터가 쌓일수록 계속 다시 적합할 수 있는 **ridge 회귀 계수**로 전환했다 (`services/predictor/models/fitted_weights.py`).

```
score = intercept
      + coef[token]  * (KRX 마감시각 기준 Bybit 토큰 변동률, %)
      + coef[NVDA]   * Nvidia 변동률
      + coef[MU]     * Micron 변동률
      + coef[SOXX]   * SOXX 변동률
      + coef[TSM]    * TSMC 변동률
      + coef[SMH]    * SMH 변동률
      + coef[KRW=X]  * USD/KRW 변동률
      + coef[DXY]    * DXY 변동률
      + coef[^TNX]   * 미국10년물 변동률
      + coef[^VIX]   * VIX 변동률
      + coef[BTC]    * BTC 변동률
      + coef[ETH]    * ETH 변동률
```
계수는 종목별로 따로 적합(삼성전자/SK하이닉스 계수가 다름). 결측 입력은 기여도 0으로 처리(가중평균처럼 재정규화하지 않음 — 회귀 계수는 그렇게 다루면 안 됨).

**토큰 베이시스 기준시각 버그(실측으로 발견, 수정 완료)**: 최초 구현은 Bybit **일봉**(UTC 00:00~24:00)에서 KRX 마감일과 같은 날짜의 종가를 기준가로 썼는데, KRX 마감(UTC 06:30 ≈ KST 15:30)이 그 UTC 일봉 구간의 초반부라 "그날 일봉 종가"가 사실상 익일 KST 08:59까지의 가격을 반영해버렸다. 조회 시점이 마침 그 근처면 기준가=현재가가 되어 token_change가 0으로 수렴하는 결함이 실제로 재현됨. `collectors/tokenized.fetch_bybit_close_at_krx_close()`가 **시간봉**으로 KRX 마감 시각에 정확히 맞춰 기준가를 잡도록 수정했다.

### 4.2 검증 결과 (2026-08-06 백테스트)
동일 40일 표본(2026-06-05~08-04, KOSPI 사상 최대 등락일 2026-07-31 제외), 동일 naive 기준선으로 비교한 MAE:

| 방식 | 삼성전자 | SK하이닉스 |
|---|---|---|
| naive("어제와 동일") | 5.28% | 6.50% |
| 손으로 찍은 가중치 | 4.76% | 5.50% |
| ridge (in-sample) | 4.65% | 5.52% |
| **ridge (LOOCV, 진짜 out-of-sample)** | **4.93%** | **5.88%** |

솔직한 결론: 둘 다 naive는 이기지만, ridge가 손으로 찍은 가중치보다 낫다고 단정할 수 없다 (표본 40일에서 차이가 노이즈 범위). ridge를 채택한 이유는 데이터가 쌓일수록 재현 가능하게 재적합할 수 있고, 이후 LightGBM/XGBoost로 넘어갈 때 같은 파이프라인을 그대로 쓸 수 있기 때문. 현재는 "정확도 낮음/검증 중" 상태로 프론트에 표시해야 한다.

같은 표본에서 확인한 상관관계도 참고: 토큰가↔실제 KRX 같은날 상관계수(삼성 0.307, SK하이닉스 0.401), 해외 프록시 lag-1 상관계수(0.24~0.43, 전부 양수) — "이 신호들이 KRX 가격과 무관하다"는 가설은 기각됨.

### 4.3 고도화 (ML)
- 데이터가 더 쌓이면(최소 3~6개월) ridge를 LightGBM/XGBoost로 교체, quantile loss로 점추정 대신 **예측 구간**을 직접 학습
- **요일별 모델 분리**: 금요일→월요일(주말 포함, 해외 영향 큼) vs 평일→익일(국내 수급 영향 큼)
- **국내 수급 신호(공매도/외국인·기관 순매수) 연동이 다음 우선순위** — 2026-07-31 KOSPI 사상 최대 상승일(최태원 회장 장내매수+숏스퀴즈)처럼 현재 모델이 못 잡는 이벤트가 정확히 이 신호 영역이었음

### 4.4 백테스트 (출시 전 필수)
서비스 오픈 전, 과거 1~2년치 데이터로 위 계산식을 백테스트해서 실제 예측력이 있는지 검증한다 (4.2는 40일치 소규모 검증 — 데이터가 더 쌓이면 훨씬 긴 기간으로 재검증 필요). 초기 "정확도 xx%" 표시는 이 백테스트 결과를 사용한다 (실운영 이력이 쌓이기 전까지 가짜 숫자를 보여주지 않는다).

## 5. 화면 구성

### 5.1 메인 (`/`)
삼성전자 카드 + SK하이닉스 카드. **정규장 운영 중(09:00~15:30 KST)엔 실제
체결가만 보여주고 예측 자체를 계산하지 않는다** (`market_hours.get_session()`
분기, 사용자 요청으로 확정). 장외/주말엔:
- 현재가(직전 KRX 종가), 추정가격, 등락률
- 상승확률, 신뢰도
- 예상 변동폭 (예측 구간)
- 영향요인 — Chart.js 다이버징 바 차트로 표시 (텍스트 리스트에서 교체됨)

### 5.2 예측 기록 (`/history`)
최근 100일: 예측가격 / 실제가격 / 오차(%) / 누적 정확도(최근 30일·100일) / 평균오차 / RMSE / MAPE

### 5.3 관리자 (`/admin`)
- 데이터 새로고침 (수동 트리거)
- 예측 다시 계산
- API 상태 (각 데이터 소스별 최근 수집 성공/실패)
- 로그

## 6. 수집 주기
데이터 소스마다 실제 갱신 빈도가 다르므로 일괄 10분 주기가 아니라 **소스별로 다르게** 스케줄링한다.

| 소스 | 주기 | 비고 |
|---|---|---|
| SAMSUNGUSDT/SKHYNIXUSDT(Bybit) | 5분, 24/7 | 주말에도 계속 수집. 실제 구현은 scheduler.py가 이 주기로 전체 파이프라인을 재실행 |
| 미국 주식(MU/NVDA/SOXX/TSM/SMH) | 매 실행마다 재조회 | 실측상 미국장 휴장 시간엔 값이 그대로(전일 종가 반복)라 낭비지만, 현재는 소스별 캐싱 없이 매번 재조회함 (TODO) |
| 환율/DXY/VIX/BTC/ETH | 매 실행마다 재조회 | 위와 동일 |
| 외국인/기관 순매수(네이버) | 1일 1회 (하루 첫 실행 시) | `main._maybe_collect_flows`가 KST 날짜 기준으로 하루 1회만 스크래핑 |
| KRX 시간외 단일가 | 미구현 | `collectors/krx.fetch_after_hours_price` 스텁 |

**주말 처리**: 금요일 KRX 마감 후 ~ 월요일 재개 전까지는 Bybit 토큰가가 유일한 실시간 신호. 실제 구현은 `market_hours.get_session()`이 토·일을 "closed"로 판정해 추정 모드로 전환하고, 2차 신호(해외 프록시)는 매 실행마다 그대로 재조회한다 (요일별 분리 모델은 아직 미구현, 4.3 참고).

## 8. 기술 스택
- **웹**: Next.js 15 (App Router, 정적 export) + React + TypeScript + TailwindCSS + shadcn/ui + Chart.js
- **데이터/ML**: Python (수집기 + ridge 회귀, 추후 LightGBM/XGBoost)
- **DB**: Supabase (Postgres) — 아직 실제 프로젝트 미생성, 현재는 predictions.json 파일 브리지로 대체
- **배포**: GitHub Pages (GitHub Actions로 predictor 실행 → 정적 빌드 → 배포). 현재 보류 중, `workflow_dispatch`로만 수동 실행 가능
- **알림**: 텔레그램 봇으로 관리자 파이프라인 장애 알림
- 역할 분리: Python이 수집·계산·저장까지 담당, Next.js는 predictions.json(추후 Supabase)을 읽어서 보여주는 역할 + 관리자 트리거용 API

자세한 구조는 [ARCHITECTURE.md](./ARCHITECTURE.md) 참고.
